# Long-context DNA models do not use the allele

An audit of DNALongBench's eQTL task (eQTLP). Findings in brief:

- Variant-to-TSS distance alone beats every published model on the released split.
- On a distance-matched, chromosome-held-out rebuild (eQTLP-v2), no model beats a
  local-composition floor (AUROC 0.599).
- Swapping the alt allele for the reference changes AUROC by at most ~10^-3 for the CNN,
  frozen HyenaDNA and Caduceus probes, and end-to-end fine-tuned HyenaDNA.
- A matched ClinVar regulatory set gives the same null result.

## Reproduce

```bash
pip install -r requirements.txt
bash fetch_data.sh            # DNALONGBENCH @ 2c4060a + eQTL data, pinned and checksummed
python analysis/eqtl_leakage.py --root data/eQTL      # distance alone: mean test AUROC 0.751
```

**[REPRODUCE.md](REPRODUCE.md)** maps every claim in the paper to the command that produces
it, the expected number, and the run time. Each command rewrites a committed result file, so
`git diff` is the check. The CPU results and the released-code defects take minutes. The
probe results need no GPU, because our embeddings are on the
[`data-v1` release](https://github.com/karan-nanda/Extending-DNALongBench/releases/tag/data-v1).

Not in the repo, all fetched by `fetch_data.sh`: the DNALongBench code and eQTL data
(Dataverse doi:10.7910/DVN/YUP2G5), the HyenaDNA and Caduceus weights (Hugging Face), our
embeddings, and the ClinVar 2026-09-05 / GENCODE v50 inputs.

## Environment

Python 3.12 with `requirements.txt` for everything except Caduceus, which needs `mamba-ssm`
in a separate Python 3.10 env (`bash analysis/caduceus_env_setup.sh`, prebuilt wheels, no
nvcc). Developed on Windows 11 + WSL2 Ubuntu 24.04 with one RTX 3060 (12 GB). On Windows, run
Python with `-X utf8`.
